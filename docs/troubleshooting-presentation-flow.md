# 센서 트러블슈팅 발표 흐름

작성일: 2026-10-11

## 1. 중계 서버 통신의 부하

센서값은 중계 서버를 거쳐 관제로 전달한다. 빠른 주기로 전송하면 송수신·메시지 처리 부담이 증가한다. 개발 경험은 서버 부하이며, 개선 전 펌웨어 주석은 100ms 전송이 제어 명령 수신을 방해했다고 설명한다. 서버 부하와 보드 통신 병목의 정확한 위치·크기는 실측으로 구분해야 한다.

## 2. 첫 대응은 1초 주기로 늦추기

개선 전 STM32는 약 1초마다 센서를 읽고 전송했다. 현재는 약 10ms 가속도 취득과 구간 계산을 분리했다. 당시 1초 설정은 네트워크 지연이 항상 1초라는 뜻이 아니라 취득·전송 간격을 늘린 것이었다.

## 3. 순간 취득의 미탐

주기 사이에 큰 양·음 변화가 있어도 읽는 순간의 가속도가 비슷하면 관제에 변화가 작게 보일 수 있다. 지진 중에도 가능한 미탐 경로다. 가속도는 위치값이 아니므로 “같은 위치를 찍었다”보다 “비슷한 가속도 시점만 포착했다”로 설명한다.

## 4. STM32 내부 취득·계산 개선안

센서는 빠르게 읽고 최근 여러 샘플로 계산한다. 구간은 최근 일정 시간의 값 여러 개를 모아 보는 범위다. 예를 들어 10 ms 취득·20개 이동 구간은 약 200 ms를 대표하며 새 값이 들어오면 가장 오래된 값을 빼고 갱신한다. 현재 적용된 설정이며 실제 수집 간격과 임계값은 실험으로 검증해야 한다.

최대-최소 차이는 가장 큰 변화 폭, RMS는 양수·음수가 상쇄되지 않는 구간 전반의 크기를 본다. 두 수치를 서로 직접 비교하는 것이 아니라 각각 정상 데이터로 정한 기준과 비교한다. 현재는 정상/이상 변화의 최소 보고 간격을 200ms로 제한하고 같은 상태는 1초마다 보고한다. 후보 지속 조건·등급별 이벤트·측정 시각 정렬은 미구현 제안이다. 관제는 현재 최신 수신 상태를 결합한다.

## 5. 가속도계의 잡음

MPU6050는 가속도계와 자이로를 포함한다. 현재 코드는 가속도계만 사용한다. 자이로는 각속도를 측정하므로 “자이로 센서의 가속도”로 부르지 않는다. 센서값에는 잡음과 일상 진동이 섞일 수 있으며 현재 잡음의 정도는 미측정이다.

## 6. FIR/IIR 적용 가능성

필요한 신호 대역을 보존하면서 불필요한 잡음 대역을 줄이는 FIR/IIR을 검토할 수 있다. 신호와 잡음 대역이 겹치면 단순 필터만으로 구분하기 어렵다.

## 7. 연산 부담과 필터 자체의 지연

필터 연산 시간이 추가될 수 있고, 과거 샘플을 조합하는 필터 자체의 시간 반응도 영향을 준다. 일반적인 선형 위상 FIR은 `(N-1)/(2fs)` 군지연을 갖는다. 100 Hz의 5탭은 20 ms, 21탭은 100 ms다. IIR도 무지연이 아니며 실제 경보 지연은 구간·임계값·처리 시간과 함께 측정한다. [SciPy FIR](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.firwin.html), [군지연](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.group_delay.html)

## 8. 초기 미사용의 근거와 검증 계획

개발자는 작은 이상 변화와 짧은 진동의 관측, 응답성을 우선해 검증 전 소프트웨어 FIR/IIR 적용을 보류한다는 설계 근거를 제시했다. 필터가 피크를 감쇠하거나 추가 지연을 만들 가능성을 고려한 선택이며, 필터 비교 실험 결과는 아니다.

적절한 필터는 오히려 감지를 도울 수 있고 미적용은 오탐을 늘릴 수 있다. 구간 RMS에도 시간 반응·피크 희석 영향이 있으므로 무지연을 주장하지 않는다. 빠른 취득을 확보한 뒤 필터 전후 미탐·오탐·종단 지연을 비교해 재검토한다. 센서 내부 DLPF와 anti-alias 처리는 별도로 확인한다.
